# PredictFlow

> **Pay for market access. Predict on-chain. Decide with confidence.**

A demo dApp for **Sui Overflow 2026 / ON THE MOVE** that composes three Sui primitives into a single product flow:

1. **Sui Payment Kit** — real on-chain payment with payment intent, receipt object, and on-chain duplicate prevention.
2. **DeepBook Predict** — oracle-priced, expiry-based binary and vertical-range positions, minted on-chain.
3. **Bounded Agentic Commerce** — a user-authorized research budget cap. The agent helps prepare research and intents within that cap, but every final financial action requires the user's signature.

PredictFlow demonstrates a full BTC/USD prediction flow on **Sui Testnet**: connect Slush wallet → authorize a research budget → explore live markets → simulate a binary or range position priced by the real oracle → place a prediction in **one signed PTB** (fee payment + position mint, atomically) → review and redeem positions in a Portfolio.

## ✨ Features

- **Wallet connect** via Slush / Sui Wallet Standard, with network detection and 5 explicit error states (not installed / rejected / wrong network / no account / timeout).
- **Research budget cap** — authorize an on-chain spend cap (default 5 DUSDC). Spending happens per prediction (fixed 1 DUSDC research fee). Remaining is verified on-chain.
- **Live BTC/USD markets** with oracle status, expiry countdown (15-min ladder), and vault summary read from the Predict server.
- **Binary and vertical-range simulators** using real `get_trade_amounts` / `get_range_trade_amounts` pricing on testnet, with a simplified formula as an automatic fallback.
- **One-signature placement** — payment (Payment Kit) + position mint (DeepBook Predict) bundled into a single PTB, producing a real digest visible on the explorer.
- **Payment receipt** (`receiptId`, nonce, amount, asset, recipient, tx digest, network) — copyable, exportable as JSON, with an explorer link.
- **Portfolio** — open and settled positions, PnL, redeem and withdraw flows.
- **AI research panel** — *deterministic, template-based, not an LLM*. Guardrails prevent the words `buy / sell / guaranteed / safe bet / sure thing / win / profit / "you should"`. It only describes what a market represents, the payoff mechanics, risks, and what the user should verify.
- **Simulated fallback throughout** — the app stays usable when testnet endpoints are unreachable.
- **Accessibility** — focus-visible rings, keyboard nav, badges with icon + label (never color alone).

## 🚀 Getting started

### Prerequisites

- [Node.js 20+](https://nodejs.org/)
- [pnpm](https://pnpm.io/) (recommended) — `npm install -g pnpm`
- A Sui wallet that supports the Sui Wallet Standard. The demo is built and tested with [Slush](https://slush.app/).
- For live mode: a Sui **Testnet** account funded with **SUI** (gas) and **DUSDC** (DeepBook Predict testnet stablecoin).

### Install and run

```bash
pnpm install
pnpm dev
```

Then open [http://localhost:3000](http://localhost:3000).

### Environment

Copy [`.env.example`](./.env.example) to `.env.local` and adjust as needed:

```bash
cp .env.example .env.local
```

The interesting flags:

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_DATA_MODE` | `simulated` (default, safe) or `testnet` (live) |
| `NEXT_PUBLIC_PAYMENT_MODE` | `simulated` or `testnet` for Payment Kit |
| `NEXT_PUBLIC_PREDICT_SERVER` | DeepBook Predict server URL |
| `NEXT_PUBLIC_PREDICT_PACKAGE` / `NEXT_PUBLIC_PREDICT_REGISTRY` / `NEXT_PUBLIC_PREDICT_OBJECT` | DeepBook Predict on-chain IDs (testnet) |
| `NEXT_PUBLIC_DUSDC_TYPE` / `NEXT_PUBLIC_PLP_TYPE` | Asset and LP token types |
| `NEXT_PUBLIC_PAYKIT_NAMESPACE` / `NEXT_PUBLIC_PAYKIT_REGISTRY` | Payment Kit IDs (testnet) |
| `NEXT_PUBLIC_MERCHANT_ADDRESS` | Demo merchant receiving the research fee |

> The testnet package IDs in the committed `.env` are demo values. They can change at any time and are **not** suitable for any production use. If you fork this, point at packages you control.

### Scripts

```bash
pnpm dev          # Next.js dev server
pnpm build        # Production build
pnpm start        # Run the production build
pnpm lint         # ESLint
pnpm typecheck    # tsc --noEmit (strict)
```

Tests (via the installed binaries):

```bash
pnpm exec vitest                  # unit + component tests
pnpm exec playwright test         # end-to-end (first run: `pnpm exec playwright install`)
```

## 🧭 The 7-step demo flow

The `AppShell` stepper maps to these screens (step index in parentheses):

1. **Connect (0)** — Landing → Slush connect → wallet status.
2. **Budget (1)** — Authorize an on-chain research budget cap.
3. **Pay (2)** — Per-prediction Payment Kit intent (bundled into the placement PTB).
4. **Explore / Markets (3)** — Live BTC/USD market cards, oracle status, vault summary.
5. **Simulate (4)** — Binary or vertical-range simulator with real oracle pricing.
6. **Review (5)** — Final review: **Preview-only by default**, Live action requires testnet + wallet + balances.
7. **Portfolio** — Open and settled positions, PnL, redeem and withdraw.

## 🔒 Safety rails the code enforces

These are project rules that apply to anything generated or contributed:

- **No secrets in storage.** Only non-sensitive receipts are persisted.
- **User signature gates everything.** Final financial actions always require explicit user signature; Review defaults to Preview Only; no tx is auto-submitted.
- **Adapter + data mode.** All market and vault data flows through `src/lib/predict/`. Live RPC is never called without an automatic simulated fallback.
- **Transparency.** Recipient and amount are always shown before any sign step.
- **AI panel guardrails.** The research panel uses a deterministic template and a banned-word guard (`buy / sell / guaranteed / safe bet / sure thing / win / profit / "you should"`). Tested.
- **Design system is frozen.** Visual components use `predictflow.css` classes — no inline restyling, no shadcn or raw Tailwind for brand visuals.

See [`CLAUDE.md`](./CLAUDE.md) for the full set of rules.
